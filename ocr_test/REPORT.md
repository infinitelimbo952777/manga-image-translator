# OCR 引擎对比测试报告

日期：2026-09-12 ｜ 设备：RTX GPU (CUDA) ｜ 测试套件：`ocr_test/`
最新基准：`logs/bench_20260912_134222.{json,csv}` + `bench_summary_20260912_134222.md`（30 页 / 120 裁剪，含彩字样式）

## 结论（TL;DR）

**推荐 Hayai OCR v2 作为本管线主力 OCR**（已接入，web UI 默认已切换）：

- 综合平均 CER **0.086 全场第一**（48px 0.104、paddle 0.332、mocr 0.768）
- 竖排日文近乎零错（0.007），英/日/韩 × 横/竖全部可用
- **彩字鲁棒性最佳**：彩色实心/深底白字/白字黑描边三种样式下几乎没有退化（见下文样式表）
- 真实漫画页对比中完美复原其他引擎全部漏掉/识别失败的竖排列，速度最快（8 行 0.35s）
- 输出格式与现有管线完全一致（text/prob/字体颜色），翻译器无需任何改动

## 部署

| 引擎 | 版本 | 设备 | 备注 |
|---|---|---|---|
| 48px (repo) | 内置 ocr48px | cuda | 基线 |
| MangaOCR | manga-ocr 0.1.14 | cuda | 基线 |
| **Hayai OCR v2** | hayai-ocr 2.1.0（HF: JustANormalTinkerer/hayai-ocr-v2, ~150M） | cuda | 首次运行自动下载 ~600MB；Windows 需 `TORCHDYNAMO_DISABLE=1`（模块内已处理） |
| PaddleOCR | paddleocr 3.7.0 + paddlepaddle 3.2.0 **CPU** | cpu | **GPU 版不可用**：torch(cu132) 与 paddle(cu126) 的 cudnn DLL 同名不兼容，同进程必崩；paddlex 3.7 import 链会拉 torch，子进程隔离也无效 |

## 方法

- **A 段（rec-only）**：30 张合成漫画页 = 12 张基础页（黑字白底）+ **18 张彩字样式页**（3 语 × 横竖 × 3 样式），切出 120 个真值行裁剪，所有引擎识别同一批裁剪。彩字页复用基础页的完全相同文案与排版，**CER 差值即"颜色/样式因素"的净影响**。
  - `color`：红/蓝/黄/粉实心字，白底
  - `dark`：深灰蓝底（气泡感），白字与金黄字交替
  - `outline`：白字黑描边（漫画 SFX 经典样式）
- **B 段（管线模拟）**：同一 CTD 检测结果（AABB 裁剪）喂给所有引擎，按 IoU 匹配真值行后算 CER。
- **真实图**：`F:\jian\picture\...\03_002.webp`（8 个检测行，竖排日文）。
- 指标：CER（Levenshtein/真值长度，归一化空白与引号）、exact-match、单裁剪延迟（3 次中位数）。

## 结果

### 综合平均（A 段 120 裁剪，CER ↓ / ms/裁剪）

| engine | avg CER | avg ms | load |
|---|---|---|---|
| **hayai** | **0.086** | 216 | 26s |
| 48px | 0.104 | 238 | 0.7s |
| paddle | 0.332 | 45 (CPU) | 5s |
| mocr | 0.768 | 133 | 11s |

### 语言 × 排向明细（A 段 CER）

| engine | ja/h | ja/v | en/h | en/v | ko/h | ko/v |
|---|---|---|---|---|---|---|
| 48px | 0.000 | 0.043 | 0.000 | 0.542 | 0.034 | 0.005 |
| **hayai** | 0.044 | 0.007 | 0.002 | **0.404** | 0.005 | 0.052 |
| mocr | 0.006 | 0.015 | 1.027 | 1.000 | 1.193 | 1.368 |
| paddle | 0.000 | 0.018 | 0.000 | 0.928 | 0.025 | 1.018 |

（48px/hayai 的日文误差基本都是标点差异；mocr 仅日文；en/v 为旋转 90° 文本，所有引擎都不行）

### 彩字样式影响（A 段 CER，同文案配对对比）

| engine | plain | color | dark | outline |
|---|---|---|---|---|
| **hayai** | 0.079 | 0.081 (+0.002) | 0.090 (+0.011) | **0.099 (+0.020)** |
| 48px | 0.072 | 0.071 (+0.000) | 0.109 (+0.037) | 0.195 (**+0.123**) |
| mocr | 0.776 | 0.747 | 0.753 | 0.788 |
| paddle | 0.332 | 0.329 | 0.331 | 0.334 |

分语言看（plain→outline）：48px 的英文 0.216→0.500、日文深底 0.000→0.107，劣化明显；hayai 各语言几乎持平（ja 0.023→0.025，en 0.202→0.204，ko 0.011→0.070）。hayai 的彩字错误仍以标点为主，唯一的实质错误是 1 例韩文竖排叠字（만남→만난남）。

**结论：彩字/深底/描边文字请选 hayai；48px 只在黑字白底场景保持满血。**

## 接入（已完成）

- `manga_translator/ocr/model_hayai.py`：仿 ModelMangaOCR —— 48px 模型出字体颜色/置信度，Hayai v2 出文本（批量推理）；竖排列以正立竖列喂给模型（与训练域一致）。
- `manga_translator/config.py`：`Ocr.hayai = "hayai"`；`ocr/__init__.py` 注册；`requirements.txt` 加 `hayai-ocr`。
- Web UI：OCR 下拉新增「Hayai OCR v2(日/中/韩/英,竖排优)」并设为默认（settings key v2→v3）。
- CLI/config.json：`"ocr": {"ocr": "hayai"}`。
- 通过 repo `dispatch(Ocr.hayai, ...)` 全链路功能验证 + web API 端到端验证（HTTP 200 有效图片）。

## 局限与备注

- **所有引擎都无法识别竖排英文**（旋转 90° 文本）——如需支持要在检测/预处理阶段做旋转归一，与 OCR 引擎无关。
- 48px 对描边字（SFX）识别与取色都明显劣化；若漫画图多 SFX 描边字，hayai 是唯一稳健选择。
- PaddleOCR 若未来需要 GPU：需与 torch 二选一独立进程部署，或等 cudnn 依赖解耦。
- 复现：`python ocr_test/generate_test_images.py && python ocr_test/run_benchmark.py --engines 48px,mocr,hayai,paddle --sections a,b --repeats 3 && python ocr_test/real_image_test.py`
